# 支援元サーチ（似た活動の団体の支援元から、知られていない助成金を探す）設計

2026-10-11 なおこさんと相談して決定。レポートとダッシュボードに表示する機能の名前は「支援元サーチ」。

## 目的

ニュースや助成金のまとめサイトに載らない助成金（地元の企業・小さな財団など）を見つける。
似た活動をしている団体のブログ・お礼のページ・採択団体のサイトに書かれた助成元の名前を手がかりに、
その助成元の**公式の募集ページ**を探し、まだ追っていない助成金をレポートの🔎新着・発見に載せる。
ブログ自体は載せない。なおこさんが👍👎で判定し、👍のものは既存の仕組みで毎週募集開始をチェックする。

## 背景（2026-10-11 時点の実績）

- 既存の「採択報告から発掘」（`news-discovery-scraper.ts`）で見つけた31件は、すべて Google ニュース経由で、
  むすびえ・ファミリーマート・サントリーなど名前の知られた助成金だった。👍は0件。
- 同じ処理の DuckDuckGo によるブログ検索は、検索語が引用符付き（`"助成を受けて" 子ども食堂`）のため
  毎週0件で、導入以来1件も見つけていなかった。引用符を外すと県のページやまとめサイトが上位になり、
  `site:ameblo.jp` などブログサービスに絞ると団体のブログが返る。
- 検索結果の抜粋には助成元の名前がほとんど入っていない（名前は記事の本文にある）。本文を読む必要がある。

## 決めたこと

| 項目 | 決定 |
|---|---|
| 読むページの集め方 | ①👍の助成金の採択団体一覧 → 団体名 → 団体のページ ②ブログサービス等の検索で活動報告・お礼のページ |
| 地域 | 愛知・東海（愛知・岐阜・三重・名古屋）の団体を先に読み、余りで全国 |
| 公式の募集ページが見つからない助成元 | 載せない |
| 動かす日 | 毎週木曜 9:00（月曜の検索とは別）。結果は候補としてDBにため、月曜の検索で取り込む |

## 流れ

1. **採択団体一覧を探す**：👍の助成金ごとに、URL（PDFなら1段上のページとサイトのトップ）から
   「助成先一覧」「助成団体」「採択結果」「支援実績」などのリンクを1つ選び、一覧（HTML/PDF）を読む。
   AIが団体名と所在地（都道府県）を取り出す。1回あたり一覧6件まで。
2. **読むページを並べる**：愛知・東海の採択団体 → 愛知・東海を含む検索語の結果 → 全国の採択団体 → 全国の検索語の結果。
   採択団体は「団体名 助成」で検索して、団体のページを1つ選ぶ。
3. **助成元を取り出す**：ページ本文をAIが読み、助成元・寄付元の名前と（わかれば）助成金名を取り出す。
4. **照合**：DBの助成元名・別名一覧（`normalizeOrgName`）と部分一致するもの、他の市区町村（`isOtherMunicipality`）、
   180日以内に調べた助成元、手がかりの団体自身は除く。
5. **公式の募集ページを探す**：「助成元名 助成 募集」で検索し、まとめサイト・ブログ・プレスリリース配信・
   ニュース・行政の他地域ページを除いた上位2件を読む。AIが「団体向けに助成・物品提供を公募しているページか」を判定。
6. **記録**：読んだページ（90日間読み直さない）・調べた助成元（180日間調べ直さない）・見つかった助成金をDBに保存。
7. **月曜の取り込み**：見つけてから60日以内の候補を、定番と同じく最初に候補へ加える（`source='trace'`）。
   以降は既存の流れ（まとめ・AI読み取り・応募可否・開始チェック）。レポートは🔎新着・発見（募集中なら🟢）。
   対象事業の欄に「手がかり：〇〇（団体名）」を書く。リンク先は公式の募集ページ。

## 上限・失敗時

- 1回あたり：読むページ30件（採択団体一覧は別に6件）、調べる助成元20件、検索40回。検索の間隔は2秒以上。
- AIは読み取りと同じモデル（`CLAUDE_MODEL`、既定 `claude-sonnet-5-5`）。費用は1週間で1ドル前後の見込み。
- ページ取得・AI・検索の失敗はその件だけ飛ばす。検索の0件が3回続いたらブロックとみなし、その回の検索を止める。
- APIキーが無ければ動かない（AIが必須）。
- 月曜の検索・手動検索と同時に動かない（`search-runner` の実行中フラグを共用）。
- 実行ごとに `trace_runs` に1行（読んだページ数・取り出した助成元数・調べた助成元数・見つかった助成金数・エラー）。
  ダッシュボードに前回の実行を1行表示する。

## DB

- `trace_pages(url PK, kind, read_at, funders)` — kind: `grant-top`（採択一覧を探した起点）/`adoption-list`/`org`/`blog`
- `trace_funders(key PK, name, program_name, clue, checked_at, result, grant_name, grant_url, benefit_type)` — result: `found`/`not_found`
- `trace_runs(id PK, run_at, pages, mentions, checked, found, error)`

## 既存処理の変更

- `news-discovery-scraper.ts`：引用符付きのブログ検索（`WEB_REPORT_QUERIES`）を削除。Google ニュースの採択報告は残す。
- `report-generator.ts`：`source='trace'` を🔎新着・発見の対象に加える。
- `search-runner.ts`：実行中の仕事の種類（検索／支援元サーチ）を持ち、ダッシュボードが区別して表示する。
- `scheduler.ts`：木曜 9:00 の実行を加える。`index.ts`：`discover` コマンドを加える。

## 確認方法

- 検索・ページ取得・AIを固定応答に差し替え、取り出し→照合→公式ページ判定→記録→月曜の取り込みを単体テストで確かめる。
- 採択団体一覧へのリンク選びは、実ページ（`tests/fixtures/trace-*.html`：ベネッセこども基金・NAGASEこどもみらい財団・
  トナミ運輸松寿会・大和証券財団）で確かめる。
- 本番で1回だけ実AIで動かし、見つかった助成金をなおこさんと確認してから、木曜の自動実行を反映する。

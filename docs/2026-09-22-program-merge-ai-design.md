# 助成金をプログラム単位で管理し、同一判定と募集開始チェックをAIに任せる

作成日: 2026-09-22

## 背景（本番で確認した問題）

2026-09-22 時点のレポートで、募集予定に66件あり、うち51件は愛知県VCのページに
載っていた過去ラウンド（「終了」表示）である。次の4つの原因で、発表済みの
助成金が募集予定に残り、同じ助成金が2行に分かれていた。

1. **再確認の対象が狭い。** 毎週公式ページを見に行って募集開始を検知するのは、
   定番リスト（7件）と👍関係あり（13件）だけ。残り46件は誰も再確認しない。
2. **表記が変わると別の助成金になる。** 年度を除いた名前に13文字以上の共通部分が
   ないと同一とみなさない。例：「2026年度 八嶋佳子基金「女性や子どもを支援する
   事業への助成」」（募集予定）と「2027年度 八嶋佳子基金助成」（募集中）。
   日本郵便年賀寄付金も同様。
3. **👍の行があると新年度の行が消える。** 同一と判定された行をまとめるとき、
   👍の行（200点）を残し、募集中の新年度の行（100点）を捨てる。捨てた側の
   状態・締切・URLを残す側に取り込まないため、未来応援ネットワーク事業は
   令和9年度（2026/8/7〜9/18）が募集中の間ずっと「未発表」と表示された。
   さらに👍行の週次チェックは行に保存されたURL（`miraiouen_r8`＝昨年のページ）を
   読むため、新年度の告知を検知できない。
4. **情報源に載っていない。** CBCチャリティ募金は愛知県VCにまだ2025年分しか
   ない。愛知県共同募金会のハブページには2026年分（令和8年9月14日〜10月19日）が
   載っているが、受付期間が全角数字で書かれていて日付を読めず、要確認扱いになった
   うえ、原因3と同じ仕組みで古い行に吸収されていた。

## 方針

助成金を「毎年続くプログラム」として1行で管理し、その年の「回」の情報で状態を
更新する。同じ助成金かどうか、新しい回が告知されたかどうかの判断は、文字列の
規則ではなくAIに任せる。👍👎メモはプログラムに付き、年度が変わっても引き継ぐ。

Dev Council（2026-09-22）の結論に従い、次の順で進める。

## 段階1：先に入れる小さな修正

### 1-1. まとめる処理で、捨てる側の新しい回の情報を残す側に取り込む

`dedupeAcrossSources()`（`src/scrapers/index.ts`）で、同一と判定した行を
捨てるとき、捨てる側が「新しい回」なら、その回の情報を残す側に取り込む。

- 「新しい回」の判定：捨てる側が募集中で残す側が募集中でない、または
  捨てる側の回の日付（募集中なら締切、募集前なら `expectedPeriod` の最後の
  年付き日付）が残す側より後。
- 取り込む項目：`status`、`applicationDeadline`、`expectedPeriod`、`url`、
  `name`（残す側が定番 `known` または手動 `manual` のときは名前を変えない）、
  `grantAmount`・`grantPeriod`・`targetProjects`（残す側が空・要確認・不明のとき）。
- 取り込まない項目：`id`、`memo`、`manualUrl`、`humanJudgment`、`source`。
- 取り込んだときはコンソールに1行記録する
  （`  ↻ 新しい回を取り込み: <残す側の名前> ← <捨てる側の名前>`）。

これで原因3が解消し、原因4も1-2と合わせて解消する。

### 1-2. 愛知県共同募金会スクレイパー

ハブページ `https://akaihane-aichi.jp/pages/38/` の `/pages/45/` へのリンク
ブロックは、表を含んでいる。表の1列目に ｢〜事業費｣ が複数、2列目に受付期間
（全角数字。例「令和８年９月14日～10月19日（必着）」）がある。

- リンクブロック内の表から、｢｣「」で囲まれた名前を1件ずつ取り出し、それぞれを
  受付期間付きの Grant にする（URLは `/pages/45/`）。
- 日付解析の前に全角数字を半角にする（`BaseScraper` に補助関数を足す）。
- 既存の「表の行」「表の外のリンク」の処理はそのまま。

## 段階2：AI照合（同一判定）

### データ

`grants` テーブルに `aliases TEXT NOT NULL DEFAULT '[]'` を追加する
（`database.ts` の ALTER TABLE 配列に追加。既存DBの移行は不要）。
JSON配列で、要素は `{ "name": string, "organization": string, "id": string }`
（`id` は情報源が付けた元の id）。

### 3層の判定

1. **別名一致**：候補の id、または名前＋助成元が既存行の別名一覧に一致すれば、
   その行の回として扱う。AIは呼ばない。
2. **候補の絞り込み**：既存の文字列規則（`normalizeOrgName` による助成元の一致・
   名前の正規化）は、AIに渡す組の絞り込みだけに使う。同じ助成元で、既存行と
   一致しない候補があるときだけ AI に渡す。
3. **AI判定**（新規 `src/enrich/ai-matcher.ts`）：助成元ごとに、既存行の一覧
   （id・名前・別名・前回の期間）と候補の一覧を渡し、候補1件ごとに
   `{ candidateId, decision: "same_round" | "new_round" | "new_program",
   programId }` を返させる（構造化出力。`ai-enricher.ts` の呼び出し方と同じ）。
   - `same_round`：同じ回の重複（別サイトに載った同じ告知）。残す側に情報を補う。
   - `new_round`：同じプログラムの新しい回。段階1-1のルールで回の情報を取り込む。
   - `new_program`：別のプログラム。新しい行として残す。
   - 判定した対応は別名一覧に追記する。
   - APIキー未設定・AI失敗・不正な id を返した場合は「まとめない」
     （2行のまま出す。消えるより見える方がよい）。
   - 判定は `search_log` とコンソールに1行ずつ残す。

### プロンプトに入れる判断基準

- 同じ助成元で、年度・回数・「【一般枠】」などの枠の表記だけが違う名前は同じ
  プログラム。
- 同じ助成元・同じ締切でも、プログラム名が違えば別（例：キユーピーみらいたまご
  財団の A／B-1／B-4、WAM の通常／モデル／補正、ミダス財団の2プログラム）。
- 同じプログラムの春募集と秋募集は同じプログラムの別の回。

### まとめた結果の表示

レポート下部に「今回まとめた行」の一覧を出す（「Y を X にまとめました」）。
誤ってまとめられたことに人間が気づけるようにする。

## 段階3：募集開始チェックのAI化

`known-grants-checker.ts` の正規表現による検知をやめ、AIによる判定に置き換える。

- 対象：募集前の全プログラム（定番・👍に限らない）。
- 読むページ：行の `manualUrl`、`url`、その団体の助成トップページ
  （URLのパスを1段上がったもの）。本文を AI に渡し、
  `{ announced: boolean, period: string, deadline: string, url: string }` を返させる。
- 見つからなければ、既存の DuckDuckGo 検索（`news-discovery-scraper.ts`）で
  「<プログラム名> <今年>」を検索し、上位の公式ページ（`NON_OFFICIAL` を除く）を
  同様に読む。
- AIが返した締切は「未来かつ1年以内」の検証を通ったときだけ採用する。
- 上限：1回の実行でページ取得は最大80件、検索は最大30件。超えた分は募集前のまま。
- 失敗時は募集前のまま。判定はコンソールと `search_log` に残す。

## 段階4：表示

- 「昨年実績」を「前回」に変える（今年の回が終わっただけの行にも「昨年」と
  出るため）。
- 行名はプログラム名を主に、今回の回の名前を締切欄に添える。

## 確認方法

- Vitest を導入する。まとめる処理と AI照合の判定は、AI呼び出しを固定応答に
  置き換えた単体テストで確認する。
  - まとめるべき組：八嶋佳子基金（年度＋名前の変更）、日本郵便年賀寄付金
    （枠の表記）、未来応援ネットワーク事業（助成元の表記違い）。
  - まとめてはいけない組：キユーピー A／B-1／B-4、WAM 通常／モデル／補正、
    ミダス財団の2プログラム。
  - 同じプログラムの別の回：むすびえ 春募集／秋募集。
- AI部分は上の実データで手動確認してから本番に入れる。
- 本番投入後、初回の週次実行の「今回まとめた行」を目視で確認する。

## 費用・時間

モデルは Haiku のまま。週次実行で AI 呼び出しが最大80件ほど増え、費用は
1回あたり数十円、時間は5〜10分延びる見込み。
